# Telemetry controls

Clusterdeck usage telemetry is off by default. Enable it only by checking the onboarding control or setting:

```json
{
  "telemetry:enabled": true
}
```

You can also use `wsh setconfig telemetry:enabled=true`. Clusterdeck records no telemetry events while disabled. At startup and before recording starts after opt-in, it deletes any pre-existing unsent queue and obsolete legacy activity rows.

Enabled events use `/tevents`. Both enable and disable transitions send the client UUID and opt-out state to `/no-telemetry`; a fresh default-disabled launch sends neither. The optional `/ping` request follows telemetry consent and can be suppressed with `WAVETERM_NOPING=1`. Its per-day limit is process-local, so an opted-in restart can send another ping on the same day.

For full schemas, recipients, timing, local cleanup, update behavior, IP visibility, and operator separation, read [Privacy](./privacy).
