# Connections

Clusterdeck discovers SSH hosts from `~/.ssh/config` and `/etc/ssh/config` and represents each host as a workspace in the connection rail. Selecting one makes it the default connection for the explorer, editor, and newly created terminals.

An individual terminal can override that default through its connection control. The override affects only that terminal; it does not retarget the workspace explorer or editor.

## SSH and remote helper

Clusterdeck uses the inherited SSH connection controller. On request it installs the remote `wsh` helper at `~/.waveterm/bin/wsh`, adds `~/.waveterm/bin` to that session's PATH, and uses SSH forwarding for GUI integration and durable sessions. The directory and environment variables such as `WAVETERM` and `WAVETERM_VERSION` are retained compatibility identifiers.

If helper installation fails, ordinary SSH terminal access can still work, but remote GUI/file operations and durable-session capabilities may be limited. You can disable helper installation per connection in `connections.json` with `conn:wshenabled: false`.

## Connection configuration

Open Settings → Connections to edit `connections.json`. Per-connection values can include shell path, identity files, SSH options, connection timeout, and a password secret name. Clusterdeck also honors applicable OpenSSH configuration such as `HostName`, `User`, `Port`, `IdentityFile`, `ProxyJump`, and included files.

Host-key checking and SSH authentication remain security boundaries. Review unexpected fingerprints rather than bypassing them. See [Secrets](./secrets), [Durable Sessions](./durable-sessions), and the [wsh reference](./wsh-reference).
