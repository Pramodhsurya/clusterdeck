# Custom widgets

The right rail is configured by `~/.config/waveterm/widgets.json`. Each entry supplies display metadata and a `blockdef.meta` object describing the block to create.

```json
{
  "widget@logs": {
    "display:order": 20,
    "icon": "file-lines",
    "label": "logs",
    "blockdef": {
      "meta": {
        "view": "term",
        "controller": "cmd",
        "cmd": "tail -f /var/log/system.log",
        "cmd:login": true
      }
    }
  }
}
```

`cmd:login` starts a login shell so Homebrew and user PATH initialization apply. Commands inherit the active workspace connection unless their block metadata selects another connection.

## Widget fields

| Field | Purpose |
|---|---|
| `display:order` | Numeric rail ordering |
| `display:hidden` | Hide the entry without deleting it |
| `icon` / `color` | Font Awesome icon name and optional color |
| `label` / `description` | Visible name and explanatory text |
| `workspaces` | Restrict the widget to listed workspace IDs; omit for all workspaces |
| `magnified` | Start the created block magnified |
| `blockdef.meta` | View/controller metadata passed to the new block |

Common block definitions include:

```json
{
  "widget@project-files": {
    "icon": "folder",
    "label": "project files",
    "blockdef": { "meta": { "view": "preview", "file": "~/project" } }
  },
  "widget@dashboard": {
    "icon": "globe",
    "label": "dashboard",
    "blockdef": { "meta": { "view": "web", "url": "https://example.com/status" } }
  },
  "widget@local-shell": {
    "icon": "terminal",
    "label": "local shell",
    "blockdef": { "meta": { "view": "term", "controller": "shell", "connection": "local" } }
  }
}
```

Opening a web widget contacts its URL. Command widgets run with the permissions of the selected connection; quote commands carefully and do not place secrets in `widgets.json`. Use `wsh editconfig widgets.json` to edit the file and `wsh launch WIDGET-ID` to test an entry. JSON parse errors or an unknown view/controller prevent a widget from opening; compare against the shipped defaults when troubleshooting.

## Shipped widgets

The default rail defines explorer, editor, terminal, files, web, sysinfo, process viewer, and `htop`. The `htop` widget remains in 0.1.4 and uses `cmd:login: true`. k9s and lazygit launchers were removed; there is no AI widget.

Inspect the exact shipped definitions in [widgets.json](https://github.com/clusterdeck/app/blob/main/pkg/wconfig/defaultconfig/widgets.json). Unknown or unsupported metadata is not guaranteed to work.
