# FAQ

## Which platforms are supported?

Clusterdeck is macOS-first. The published 0.1.x package target is Apple Silicon. Code inherited from Wave may compile elsewhere, but Clusterdeck does not currently claim supported Windows or Linux releases.

## Why does macOS block the app?

Current artifacts are unsigned and unnotarized. Install from the Clusterdeck Homebrew tap, then use Finder's **Open** action or the quarantine instructions in [Getting Started](./gettingstarted). Do not bypass Gatekeeper for an untrusted artifact.

## Does every terminal have to use the workspace connection?

No. The explorer, editor, and new terminals default to the selected workspace connection. One terminal can override its own connection without changing the others.

## Why are some paths still named waveterm?

`~/.waveterm/bin/wsh`, `WAVETERM_*`, internal Go module paths, and the proper name “Wave Shell Extensions” are inherited compatibility contracts. Renaming them without migration would break remote helpers or configuration.

## Is there built-in AI?

No. The inherited AI feature and a short-lived coding-agent integration were removed for 0.1.4. Use tools installed in your terminal if desired.

## How do I report a problem?

Open an issue in [clusterdeck/app](https://github.com/clusterdeck/app/issues) with reproduction steps and logs that do not contain credentials. Use `wsh wavepath log` to locate the inherited backend log filename.
